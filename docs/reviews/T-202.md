## 评审历程

### 第 1 轮：FAIL（3 个阻塞问题）
1. **CF_DIB / CF_DIBV5 完全未读取**：只有 PNG 注册格式分支，PrtScn、老式截图工具、部分绘图软件只放 DIB 时截图静默不入库，违反「支持 CF_DIB/PNG」。
2. **RTF 按 UTF-16 启发式解码**：`read_string_from_handle` 见到偶数长度就按 UTF-16LE 解码，RTF 是 ANSI/UTF-8 字节流，约一半概率存乱码。
3. **>8MB 图片整条静默丢弃**：`read_image` 超限返回 `None`，最终 `Ok(None)`，既无条目也无标记，违反「只存缩略图并标记」。

### 第 2 轮：PASS
三个阻塞问题均已修复：

| 问题 | 修复 |
|---|---|
| DIB 未读取 | `platform/clipboard.rs` PNG 之后依次读 `CF_DIB(8)` / `CF_DIBV5(17)`；`ClipboardContent::Image { data, format: ImageFormat }`，DIB 原始字节按 `.dib` 落盘 |
| RTF 乱码 | `read_rtf` 改为 `read_bytes_from_handle` + `from_utf8_lossy`；UTF-16 解码仅用于 `CF_UNICODETEXT`，并按第一个 NUL 截断 |
| 超限图片丢弃 | 超限生成 `data` 空、`truncated=true`、`preview="[图片过大]"` 的标记条目，不写 blob；UI-SPEC §4.4 有「原图过大」标记位 |

同轮附带修复（均为评审非阻塞建议）：
- 格式常量命名：`CF_UNICODETEXT` / `CF_HDROP` / `CF_DIB` / `CF_DIBV5`
- HTML 解析优先 `StartFragment`/`EndFragment`，缺失时回退 `StartHTML`/`EndHTML`
- `GlobalSize` 先判大小再拷贝，避免超大图内存尖峰
- `DragQueryFileW` 长度 `saturating_add` + `u32::MAX` 防御
- `register_format` 返回 0 时记 debug 日志（仅格式名）
- `truncated` 只表示正文截断（预览截断不再误标）
- 文本补 256KB 上限，按字符边界截断（原 `text[..max_len]` 会切坏中文并 panic）
