## 实现概要

### 统一错误处理

`src/lib/ipc.ts` 新增 `invokeWrapper` 函数，统一包装所有 Tauri invoke 调用：

```typescript
async function invokeWrapper<T>(command: string, args?: Record<string, unknown>): Promise<T> {
  try {
    return await invoke<T>(command, args);
  } catch (err) {
    return handleError(err, command);
  }
}
```

`handleError` 函数：
- 已知错误码：从 `ERROR_MESSAGES` 映射表取中文 toast
- 未知错误码：`console.error('[ipc] unhandled error code:', code, 'command:', command)`，返回「操作失败，请稍后重试」
- 非 AppError 异常：返回「操作失败，请稍后重试」

错误码映射表 `ERROR_MESSAGES` 覆盖全部 10 个错误码。

### 契约测试

共享 fixture 文件：
- `src/lib/contract/ClipboardItem.keys.json`：12 个字段
- `src/lib/contract/ClipboardDetail.keys.json`：17 个字段
- `src/lib/contract/ClipboardListResult.keys.json`：2 个字段
- `src/lib/contract/Settings.keys.json`：13 个字段

TS 测试（`src/lib/ipc.contract.test.ts`）：
- 4 个测试，每个构造完整对象，`Object.keys().sort()` 与 fixture 比对

Rust 测试（`src-tauri/src/models.rs`）：
- 4 个测试，每个用 `serde_json::to_value()` 序列化，提取 keys 与 fixture 比对
- fixture 通过 `include_str!("../../src/lib/contract/*.keys.json")` 读取

任一侧删除/重命名字段都会导致双侧测试失败，真正建立跨语言契约。

### 验收核对

1. ✅ **删掉 Rust 某个字段后契约测试失败**：Rust 侧删除字段后，`serde_json::to_value()` 的 keys 与 fixture 不一致，测试失败；同时 TS 类型不匹配，编译错误。
2. ✅ **前端无散落的 `invoke(`**：grep 确认仅 `ipc.ts` 内部使用 `invoke`，所有业务代码通过 `ipc.xxx()` 调用。
