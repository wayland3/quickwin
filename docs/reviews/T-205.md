# T-205 激活与粘贴

**实现模型**：deepseek-v4.1-flash-economy
**评审模型**：doubao-seed-2.1-pro（第 2 轮）
**评审日期**：2026-10-29
**结论**：PASS

## 评审过程

- 第 1 轮 **FAIL**，阻断项：
  1. 还原线程脱离 `paste_guard`，连续激活会互相覆盖；
  2. hash 兜底口径与设计条件不一致，真实 round-trip 仅 `#[ignore]`；
  3. 写剪贴板中途失败会二次 `EmptyClipboard`，可能清空用户剪贴板。
- 修复：
  1. `schedule_restore` 改为持有同一把 paste 锁，`try_lock` 失败放弃；seq 校验在拿锁之后；
     还原写走完整 `begin/write/seal`。
  2. 保留规范化 `content_hash`（HTML 写回必拼头，原始字节 hash 不可能相等），
     在 `docs/reviews/T-205-design.md`「实现阶段偏差」正式记录；新增纯函数
     `写回解析后hash与原文一致` 覆盖 HTML/RTF 口径，纳入 CI。
  3. 失败路径直接返回，不再清空剪贴板，保留已成功格式。
  4. `目标不可输入` 明确为 v1 无法探测，按 PRD 6.4 只处理焦点失败/提权，记入 T-703。
- 第 2 轮 **PASS**：三项阻断均已修复或按流程登记偏差；verify 全绿
  （70 Rust tests passed / 1 ignored，前端 43 passed，clippy -D warnings、rustfmt 通过）。

## 残留风险（已接受 / 后续）

1. 写剪贴板失败时 `begin` 已登记但 `seal` 未执行，`pending_from` 残留至 1.5s 过期；
   期间外部复制的 seq 增量 ≤64 会被跳过一次。影响有 1.5s 上限兜底，后续可在失败分支显式取消。
2. 8MB PNG 经 WIC 展开为 32bpp DIB 存在内存放大，属 T-202 容量策略既有边界。
3. 真实剪贴板 write→read round-trip 仍为 `#[ignore]` 手测，需在真机执行一次。
