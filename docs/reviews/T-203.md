## 实现要点

- **新增 `services/storage.rs`**：迁移（v0 → v1）、去重入库、FTS 同步、blob 落盘、启动一致性校验
- **去重**：`sha256(kind + 规范化内容)`（文本统一换行、文件列表排序、图片含格式前缀）；重复只 `copy_count+1` + 刷新 `last_copied_at`，返回真实 id
- **事务**：主表 + FTS 同事务，失败自动回滚
- **FTS**：显式 `rowid = clipboard_item.id`；启动时行数不一致则 `rebuild`
- **事件**：`clipboard://changed { id, kind }`（500ms 节流、首条不节流）；`clipboard://insert-error { code, message }`（不节流）
- **前端**：`App.tsx` 监听 `clipboard://insert-error`，显示中文 toast（`role="alert"`，4s 自动消失）
- **生命周期**：`ClipboardMonitor` 交由 `app.manage()` 持有，修复此前 `let _monitor` 立即 drop 导致监听线程未运行的问题

## 遗留建议（非阻塞，已排期或记录）
- 节流仅 leading 语义：500ms 窗口内末次变更不触发事件，UI 依赖下次事件或面板全量重查兜底
- FTS 一致性只比较行数，rowid 不交集时漏检（T-206 前补 `NOT EXISTS` 反查）
- 启动期存储初始化失败仅记日志，UI 无感知（后续在设置页显示存储状态）
- 超大图标记条目 `byte_size=0`，且不同超大图会因空 data 被去重合并（T-204/T-206 处理）
- `write_blob` 直写而非 temp + rename（T-206 孤儿清理时统一）
- 缩略图生成、DIB→PNG 转换需 WIC，随 T-204 实现
