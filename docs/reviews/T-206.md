# T-206 保留策略与容量治理

**实现模型**：deepseek-v4.1-flash-economy
**评审模型**：doubao-seed-2.1-pro
**评审日期**：2026-10-29
**结论**：PASS（第 2 轮）

## 评审过程

- 第 1 轮 **FAIL**，3 个风险：
  1. blob 预算按 DB `byte_size` 计算，与验收「把 blob 目录塞到超限」不一致（孤儿文件不计数）；
  2. `clear_history` 只删引用 blob，`blobs/` 可能残留孤儿文件，与「清空后 blobs/ 为空」冲突；
  3. 确认条按钮获焦后 Enter 会同时触发按钮 click 与面板快捷键，存在双触发。
- 修复：
  1. 新增 `blob_usage_on_disk()`，按 `blobs/` 实际磁盘占用（含孤儿）判定预算；
  2. `clear_history(include_pinned=true)` 删除条目后 `remove_dir_all(blobs)`；
  3. 确认按钮 `tabIndex={-1}` + `onMouseDown` preventDefault，焦点保持在输入框。
- 第 2 轮 **PASS**，三处修复均已核对并有针对性测试。

## 实现概要

- `services/retention.rs`（新增）：`RetentionPolicy`（TTL 截止、条数超出、500MB 预算）、
  清理时机常量（6h / 200 写 / 孤儿 1h）。
- `storage.rs`：
  - `cleanup`：TTL（`pinned=0 AND last_copied_at < cutoff`）→ 条数（最旧非置顶）→
    blob 预算（按磁盘实际占用淘汰最旧非置顶图片）→ 孤儿回收（仅 1h 前创建的）；
    主表/FTS 同 IMMEDIATE 事务删除，blob 文件在提交后删除。
  - `clear_history(include_pinned)`：保留收藏或全部清空；全部清空后移除 `blobs/` 目录。
  - `reclaim_orphan_blobs`：未被 `blob_path` 引用且 mtime 超过 1 小时才删除。
- 监听线程：启动清理 + 每 6h + 每累计 200 次成功写入触发；删除条目后发 `clipboard://cleaned`
  通知面板刷新。暂停记录沿用 T-107 的持久化开关 + `RuntimeFlags`，暂停期间不读取、不入库。
- IPC：`clipboard_clear(include_pinned)`；前端 `Ctrl+Shift+Delete` 打开内联确认条
  （Enter 保留收藏 / Ctrl+Enter 全部清空 / Esc 取消），确认态不会触发粘贴。
- 文档：`UI-SPEC` 补键盘行，`ARCHITECTURE` 事件表补 `clipboard://cleaned`。

## 测试

- 新增 Rust 7 个：TTL + 置顶豁免、条数上限、blob 预算（DB 与磁盘口径）、清空保留收藏、
  孤儿回收、全部清空后 blobs 目录为空。
- 前端新增键盘映射与确认流测试。
- 结果：104 Rust passed / 1 ignored，前端 44 passed，`verify` 全绿。

## 遗留建议（不阻塞）

1. 清空与监听线程并发写存在窄窗口竞态（blob 已写、事务未提交时 `remove_dir_all`），
   概率低；后续可用暂停标志串行化。
2. 磁盘口径下，<1h 的大孤儿会连坐淘汰正常图片，需等孤儿满 1h 后下一轮自愈；语义已记录。
3. 确认按钮移出 Tab 序，键盘可访问性轻微回退（快捷键路径完整，可接受）。
4. 验收中「系统时间前推 16 天」需真机手测（修改系统时间），代码测试已覆盖等价逻辑。
