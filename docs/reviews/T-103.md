  1. `hotkey://failed` 前端无人监听，且 setup 阶段事件早于 WebView，托盘也无提示；
  2. rebind 存在「新旧键相同误报失败」「旧键注销失败被静默吞掉」边界缺陷；

  2. rebind：新旧键相同短路；register 失败回滚 failed 追加记录、旧键保持可用；
  3. `register_defaults` 改无返回值；lib.rs 调用处更新；`.expect(...)` 补启动期注释。
- 第 2 轮 **FAIL**：提示渲染在 `visible:false` 的不可见窗口、4s 后消失，用户实际看不到。
- 修复：浮层对用户可见后（`overlay://shown`）重新拉取状态并提示。
- 第 3 轮 **PASS（附条件）**：遗留「托盘直达只发 `overlay://show` 不重查」。
- 修复：`overlay://show` 监听也调用一次失败检查。最终 **PASS**。

## 核对通过项

- 默认三键：Alt+Space / Alt+V / Alt+X；启动时逐个注册，单个失败仅 warn，不中断其余注册；
  failed 状态持久保留，浮层可见（热键或托盘）时补中文提示「热键 X 已被其他程序占用，可在设置中改绑」。
- rebind：先注册新键，成功才注销旧键；新键冲突时 bindings 不被改写、旧键保留、返回 false。
- 旧键注销失败（罕见）：bindings 回滚为旧键、failed 以 `hotkey.unregister_failed` 记录并补发事件。
- 统一入口：global shortcut 插件仅出现在 `lib.rs` 装配与 `services/hotkey.rs`；
  commands、tray 与其他业务代码未直接注册热键。
- 生产代码无 `unwrap`/`expect`/裸 `panic`（lib.rs 启动期 expect 有注释）；日志不含敏感内容。
- verify 全绿：72 Rust tests passed / 1 ignored，前端 43 passed，clippy `-D warnings`、rustfmt 通过。

## 遗留风险（已接受）

1. 旧键注销失败分支回滚 bindings 后仍返回 `Ok(true)`，此刻新键未回收、新旧两键都触发同一 action。
   Windows 上 unregister 极少失败，记录在案；后续可改为尝试注销新键后返回 false。
2. 退出清理依赖 `tauri-plugin-global-shortcut` 插件 drop 时的隐式 unregister_all，无显式 Drop；
   需真机验证 `app.exit(0)` 路径。

## 需真机手测（待用户执行，记录 Win 版本 / 是否多屏）
