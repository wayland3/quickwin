# T-107 设置读写

**实现模型**：qwen3.7-plus
**评审模型**：GLM-5.3
**评审日期**：2026-10-29
**结论**：PASS（第 3 轮）

## 评审过程

- 第 1 轮：**FAIL**，3 个风险：
  1. 启动不读 settings 注册热键，重启后热键回退默认；
  2. 「暂停 30 分钟」实际是永久暂停，无恢复入口；
  3. settings 读-改-写无事务隔离；副作用失败策略不一致；错误码用错。
- 修复：
  1. 启动时 `load_settings` → 按存储键注册热键（失败回退默认）；`hotkey_rebind` 成功后异步写回 settings；启动对账 autostart 与 PasteOptions；
  2. `RuntimeFlags` 改为 `pause_until: Mutex<Option<Instant>>`，到期自动清除；`Some(0)` 恢复；`None` 用 1 年模拟；托盘新增「恢复记录」；前端 toast 三分支文案；
  3. `transaction_update_settings` 用 `BEGIN IMMEDIATE`；autostart 失败降级 warn；`SettingsInvalid(String)` 携带原因；新增三热键不重复校验。
- 第 2 轮：**FAIL**（窄条件）：
  - 风险 A：`lib.rs` 启动 `load_settings` 用 `?`，DB 打不开会 panic；
  - 风险 B：`transaction_update_settings` / `is_paused` / 三热键重复校验无测试。
- 修复：
  - 风险 A：改为 match 降级回退默认设置；
  - 风险 B：补 6 个测试（事务回滚/幂等/成功、暂停到期/永久/未暂停、三热键重复）；
  - 顺手修正 `set_pause_until` 过时注释。
- 第 3 轮：**PASS**，三条验收标准全部达成。

## 验收核对

- **改设置后重启保持**：✅ 启动时按 settings 注册热键；`hotkey_rebind` 成功后异步写回；autostart 启动对账；PasteOptions 同步。
- **非法值被拒绝并回退默认**：✅ `validate` 校验热键格式/保留天数/条数范围/主题/排除应用/三热键不重复；失败返回 `SettingsInvalid`（code=`settings.invalid`）；`load_settings` 解析/校验失败回退默认且不写库。
- **前端收到变更事件**：✅ `settings://changed {keys, failed}` 广播；App.tsx 监听并处理 failed（热键占用 toast）。

## 偏差与遗留（记入实现备注，不阻塞）

1. `register_startup_hotkeys` 当 configured 与 default 相同且被占用时，同一键进 failed 两次（toast 重复显示）。
2. `hotkey_rebind` 异步写回失败被 `let _ =` 静默吞掉，且成功写回不广播 `settings://changed`（T-601 设置页缓存可能不同步）。
3. 事务内重读 `unwrap_or_default()` 静默吞解析错误且不 validate，与 `load_settings` 的 warn 行为不一致。
4. autostart 失败仍只 log::warn，前端无感知（failed 列表只装热键）。
5. 启动热键注册（配置键被占用 → 回退默认 → 重启重试）属 Win32 行为，需真机手测并记录环境。
